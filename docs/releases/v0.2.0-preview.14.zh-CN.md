# 釉光 · Overglaze 0.2.0-preview.14 更新公告

本版汇总 Preview 13 准备的游戏识别、Steam 接入和 PBZ 免切档初始化改动，并补上 NR 提交登记竞争的处理。Preview 13 在收到 PBZ 运行中停止的新反馈后已撤回，其标签和源码保留；本次使用新的版本号发布。

## NR 运行中停止：修复登记竞争，保留具体错误

旧代码把多种登记失败合并成了 Live render enrollment failed。现在区分临时忙锁、上一份录制仍被持有、未观察到队列、原生命令列表不匹配及观察器真实故障。

当登记前只遇到一次元数据锁竞争，且尚未录入任何 NR GPU 命令时，只旁路当前帧，保持用户的 ON 意图，下一次可用帧重置历史后继续。真实故障仍停止，并显示具体分支与观察器最早的错误。队列身份、GPU 完成、资源生命周期等检查均保留。

这项处理位于共用运行时，不按游戏名称放行。并发合成测试已经覆盖临时竞争；旧版 PBZ 故障只留下了通用报错，不能据此声称它的唯一原因已经确证。

## PBZ：正常进场景后直接开启 NR

已验证的《影之刃零》（PBZ）构建使用随游戏启动加载，及时记录真实 DLSS 创建信息。正常进场景后按 Insert 开启 NR，不需要每次切换 DLSS 档位，也不需要旧的釉光 Steam 启动项。NR 每次启动仍默认关闭。

加载选择同时校验游戏 EXE 与三个图形模块的身份，只覆盖已验证构建。旧晚加载包会在游戏库提示配置更新，通过「更新插件」应用新策略；遇到其他工具的根目录 dxgi.dll，会在卸载当前插件之前拒绝更新，不覆盖其他工具。其他游戏和未验证构建保留原有加载方式。

## 通用游戏库与启动器修复

- 游戏库识别 7-Zip／8-Zip 独立工具，包括 8za_v2.exe 等数字版本后缀，以及 CheckEnv.exe，避免把它们当成游戏本体。仅共享名称前缀的普通游戏不会被误判。此前错装的条目仍可按文件身份卸载。
- 晚加载 Steam 启动项增加登记的游戏 ID，保留 Steam 原始命令和参数，同时按所选条目的真实 EXE 与安装身份接入。启动器和本体同名、位于不同目录时，不再因为只认首个进程而旁路；无效 ID 不会回退到其他游戏。
- Preview 12 的共用 DX12 面板绘制、帧生成面板闪烁、焦点切换和《鬼武者》绑定保护修复继续保留。

## 实测与验证范围

测试环境为 RTX 5090、驱动 621.01。

- PBZ 的免切档加载已通过两次新进程验证。
- 更新后的候选在新会话中经过用户菜单／场景切换检查，NR 从 2,928 次增加到 5,344 次；最终 5,343 次 GPU 完成、1 次在途。运行时跳帧、准入跳帧、历史中断和错误均为零，用户反馈仍然正常；控制器另保留了一次初始化网络重建记录。
- 该次实机检查没有发生忙锁跳帧。忙锁处理路径由并发合成测试覆盖，不把这次通过当成旧故障唯一原因的证明。
- 102/102 非 GPU 原生回归通过；89 项 Python 回归通过，1 项跳过；10/10 GPU 提交与面板互操作测试通过；两种真实 NR 合成宿主分别通过 1,507、2,875 项检查。

以上仍是限定条件下的功能验证，不等于全场景、长期稳定性、画质或性能已经系统验收。PBZ 的 NR＋FG 同开有暂时正常的用户反馈，也不扩展成所有游戏的兼容结论。

## 更新步骤

1. 升级釉光桌面程序，退出受影响的游戏后，在游戏库点「更新插件」。本次修改了宿主和 NR 桥，只升级桌面程序不会替换游戏里的插件。
2. PBZ 的已验证构建更新后，移除旧的釉光 Steam 启动项并正常启动；已使用普通加载的安装保持该方式。无需再切 DLSS 档位。
3. 其他仍需晚加载的游戏，从游戏库重新复制包含 --game-id 的完整 Steam 启动项。
4. 旧条目若选中了 8za_v2／CheckEnv 等工具，先卸载错装插件、移除条目，再添加游戏本体。PBZ 本体为 platform\steam\PBZ.exe。

本项目不附带、不再分发 NVIDIA NR 模型，模型属于 NVIDIA，由用户自行提供。釉光是实验性的第三方工具，与 NVIDIA 及游戏开发商、发行商没有关联或背书。
